구현한 비용 개선

01 검색불필요한 요청·큰 응답 줄이기

04 썸네일공개 파일의 CDN 재사용
  1. 검색 자동완성: 열린 드롭다운의 유효 검색어만 조회합니다. id, short_id, slug, title, summary, category 여섯 필드만 받고, 검색창 인스턴스별 30초·최대 32개 캐시로 완료된 응답을 재사용합니다. 실패·취소·오래된 응답은 저장하지 않습니다. IME 조합 중 요청과 페이지 검색을 보류하며, 조합 확정 Enter가 옛 추천 결과로 이동하지 않도록 처리했습니다. 입력 중 300ms 본문 검색은 유지됩니다.
  2. 탐색 플랫폼 집계: get_social_platform_counts가 distinct 공개 밈 수 네 행을 반환합니다. 종전 1,000행씩 전체 콘텐츠를 내려받던 경로의 전송·JS 집계 비용을 줄입니다. SECURITY INVOKER와 기존 RLS, 공개/제한 부모 밈, 승인·사용 가능 콘텐츠 필터를 유지합니다. 익명 GET 집계 응답 한 종류만 Next Data Cache에 300초 저장하고 관리자 공개 상태 변경·출처 승인 때 즉시 만료합니다. 미적용 환경은 기존 페이지 조회로 폴백하지만 일시적 오류에서 전량 조회를 추가하지 않습니다.
  3. MPE worker idle backoff: 빈 큐일 때 2→4→8→16→30초로 대기합니다. 처리할 작업이 있으면 쉬지 않고 처리하며 처리 후 간격을 2초로 돌립니다. 지속적으로 빈 큐라는 가정 아래 정상 상태의 조회 상한은 시간당 약 1,800회에서 120회로 줄어듭니다(약 93% 감소). 이는 이론값이며 실제 15,627건의 93%가 줄어든다는 뜻은 아닙니다. 신규 작업 발견·종료 대기는 기본 최대 약 30초이며 maintenance도 해당 대기만큼 늦어질 수 있습니다. 명시적 idle 설정은 최대 300초로 제한됩니다. 실행 중 worker는 재시작 후 적용됩니다.
  4. 공개 썸네일: Storage 폴백도 CDN 캐시를 허용하고, 덮어쓸 수 있는 경로의 오래된 R2 1년 immutable 정책도 브라우저 60초·CDN 300초로 제한했습니다. 새 응답에는 public, max-age=60, s-maxage=300을 적용합니다. 사용자 업로드는 소유자/승인 검증과 private, no-store를 유지합니다. 이미 예전 1년 헤더로 저장된 브라우저 캐시를 소급 만료시키지는 못합니다. 즉각적인 교체가 필요하면 새로운 파일 경로를 사용해야 합니다.
추가 Redis나 별도 벡터 DB를 도입하지 않았습니다. 현재 검색에는 이미 trigram·초성·별칭 인덱스가 있습니다. Supabase Free의 API 호출 자체는 무제한이고, 벡터 검색이 반복 호출·전송량을 자동으로 줄여주지는 않습니다. 의미 검색이 제품 요구가 되면 정확도·인덱스 크기·DB 부하를 별도 검증해야 합니다.

본문·상세·로그인 응답을 공용 CDN에 캐시하지 않았습니다. 현재 페이지는 쿠키·언어에 따라 SSR되므로 데이터 집계 캐시를 문서 CDN hit와 동일하게 계산하면 안 됩니다. 클라이언트 추천은 공개 상태 변경을 최대 30초, cron 변경에 대한 수량은 캐시 갱신까지 지연시킬 수 있습니다.
