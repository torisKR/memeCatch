### 판정

- **첫 화면에서 뜻과 상태를 바로 이해할 수 있는가 — 아니오.** 첫 뷰포트에 밈 정보가
  하나도 없다. 제목·한 줄 뜻·안전 신호·유행 상태 전부 1,344px 아래에 있고, 사용자는
  1.6 뷰포트를 스크롤해야 “이 밈이 무슨 뜻인지”에 도달한다.
- **영상이 핵심 정보를 아래로 밀어내는가 — 예.** 대표 임베드 하나가 662px, 첫
  뷰포트의 78%를 차지한다. LOOP.md 「상세 페이지 정보 계층」은 1~7번(분류·제목·뜻·
  안전 신호·맥락·검수 정보·액션) 다음 **8번**에 대표 미디어를 두라고 규정한다.
  현재는 정확히 역순이다.
- **원인은 레이아웃 순서.** `app/(default)/memes/[key]/page.tsx:221`의 2단 그리드는
  데스크톱(`lg:grid-cols-[5fr_6fr]`)에서 왼쪽=미디어 / 오른쪽=정보로 잘 동작하지만,
  모바일에서는 DOM 순서 그대로 미디어 블록 전체가 정보 블록 앞에 온다.
  → **데스크톱 레이아웃을 지키면서 모바일 순서만 바꾸는 것이 이번 개선의 핵심**
  (`DES-001`).
- **로그인 유도가 본문보다 먼저 온다.** `AuthInvite`(약 410px)가 h1보다 위에 있다.
- **출처·검수 정보가 눈에 보이는가 — 아니오.** 2,797px / 2,837px, 즉 3.3 뷰포트
  아래다. LOOP.md는 「한 번의 탭 이내」를 요구한다.
- **안전 신호와 유행 상태가 혼동되는가 — 부분적으로 예.** 정답 카드는 `Life signal`
  헤더 + `SignalTrace`(유행 상태)와 `SafetyBadge`(안전)를 분리해 보여준다. 그러나
  **안전 등급 스케일 자체에 시의성 값이 섞여 있다** — `lib/labels.ts:10`의
  `gray: 이미 늦음(사어)`. “써도 됨 / 맥락 주의 / **이미 늦음** / 쓰면 위험”은
  안전 축과 시의성 축을 한 스케일에 넣은 것이다. 유행 상태에는 이미 `식는 중`,
  `추억 밈`이 따로 있다. → LOOP.md가 지목한 `HUMAN_GATE` 항목(`HG-002`).

### 신뢰 패널

LOOP.md가 요구한 접을 수 있는 「이 설명을 믿을 수 있는 이유」 영역이 **없다.**
대신 정보가 세 곳에 흩어져 있다.

| 요구 항목 | 현재 |
| --- | --- |
| 마지막 검수일 | `updated_at`을 “마지막 업데이트”로만 표기 (2,837px) |
| 문서 상태 | `limited`일 때만 상단 배너. `approved`/보강 중 구분 없음 |
| 근거 출처 수와 역할 | 링크 3개까지만 나열. 역할(`original` 등) 표기 없음 |
| 원본 확인 여부 | 없음 |
| 권리 노출 방식 | 없음 |
| 수정 이력 | 없음 |
| 오류 제보 CTA | 「아직 정리 중」 배너 안에만 있음 |

**문구 정확성 문제:** “밈캐치 검수팀 확인”은 `description` 또는 `origin`이 있으면
무조건 렌더된다(`page.tsx:357`). 출처가 0건인 공개 문서 1,330건에도 그대로 나온다.
근거 없이 검수 완료를 주장하는 셈이다 → `DQ-001`.

### 불완전 문서 표시

`components/doc-status-note.tsx`는 **이미 LOOP.md 요구를 잘 만족한다** — 「유래·사용
예문·출처」 중 무엇이 없는지 구체적으로 지목하고 제보 경로를 연다. 문제는 노출
범위다. 이 배너가 공개 문서의 **96.3%** 에 뜬다. 파일 상단 주석이 스스로 경고한
상태(“모든 문서에 붙는 순간 의미 없는 템플릿이 된다”)에 이미 도달했다 → `DQ-002`.

또 문구에 조사 placeholder가 하드코딩돼 있다 — `「{title}」을(를) 실제로 써
보셨다면` (`doc-status-note.tsx:50`) → `DES-003`.

## 2. 랭킹 `/rankings`

본문 텍스트 정규식 검사 결과:

| 확인 항목 | 검출 |
| --- | :---: |
| 산정 기간 (`기간｜집계｜기준`) | ❌ |
| 마지막 업데이트 시점 (`업데이트｜갱신`) | ❌ |
| 표본 부족·동률 상태 (`표본｜데이터 부족｜동률`) | ❌ |

- 1·2·3·4위를 정확한 순위처럼 제시하지만 **1위 문서의 누적 조회가 53회**, 전 사이트
  누적 `view_events`가 1,298건이다. 표본이 순위 정밀도를 뒷받침하지 못한다.
- 「오늘의 급상승 / 이번 주 많이 본 / 다시 뜨는」 세 탭이 서로 다른 산식을 쓰지만
  화면에 설명이 없다.
- 운영자·봇 트래픽 제거 여부가 문서화돼 있지 않다(`increment_view` RPC는 세션×밈×일
  단위 dedup만 한다).
- **쿠팡 제휴 도크가 4위 카드를 덮는다** — 하단 고정 요소와 콘텐츠 겹침.
- 카드 자체는 잘 돼 있다: `● 써도 됨`(안전)과 `🔥 급상승`(유행)이 아이콘+텍스트로
  분리돼 있어 색상만으로 상태를 전달하지 않는다. LOOP.md 절대규칙 8 준수.

→ `DES-002`, `DES-004`

## 3. 전 페이지 공통

- **변경 안내 모달이 상세 첫 진입을 가린다.** `/memes/[key]` 첫 방문 시 「밈캐치가
  업데이트됐어요」 모달이 뷰포트 하단 절반을 덮는다. 「확인했어요 / 오늘 하루 보지
  않기」 버튼은 접근 가능한 이름을 갖고 있어 조작 자체는 문제없다.
- **쿠팡 도크가 `bottom-16`(하단 내비 위)에 고정**돼 상세·랭킹 모두에서 본문을 덮는다.
- 접근성 트리 확인 결과 헤더·내비·모달의 주요 컨트롤은 모두 접근 가능한 이름을
  갖고 있다(`밈 검색`, `메뉴`, `새 소식 닫기`, `광고 닫기` 등). 다만 **자동 검사를
  돌리지 않아 WCAG 2.2 AA 전반은 미검증**이다 → `A11Y-001`.
