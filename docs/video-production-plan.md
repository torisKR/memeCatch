# 밈캐치 영상 제작·발행 구현 계획

상태: 사용자가 확정한 **로컬 구현·검증 범위**를 완료했다. 관리자·대본·발행 계약·DB 작업 원장·실제 로컬 음성/영상 생성과 수정 범위 회귀 검사를 마쳤다. 전체 DB 체인·pgTAP·전체 빌드의 검증 제한은 별도로 기록했다. 이미 생성한 Google Cloud OAuth 클라이언트는 보존하지만 운영 DB·비밀 설정·채널 연결·업로드·배포는 진행하지 않았다. 현재 근거와 보류한 운영 활성화 항목은 `docs/operations/video-production-acceptance-20261012.md`에 기록한다.

## 목표와 경계

검수된 밈 한 개를 선택해 자체 대본·음성·그래픽으로 30~45초 세로 영상을 제작하고, 관리자에서 완성본을 검수한 뒤 YouTube 비공개 업로드, 공개/일부 공개 승인, 실제 처리·임베드 확인, 해당 밈 상세 연결까지 이어간다. 정상 경로뿐 아니라 토큰 만료, 렌더 실패, 업로드 성공 후 DB 실패, 공개 제한, 삭제 요청도 처리한다.

기존 MPE 원본 수집 작업은 변경하지 않는다. 공용 렌더 함수에는 선택적 승인 폰트 계약을 추가하되 기존 호출자의 기본 동작을 보존한다. 외부 SNS 원본을 다운로드하거나 자체 해설을 유래 검증 근거로 재수집하지 않는다. 공개는 항상 운영자의 제작물 해시별 승인에 의존한다. 새 패키지·Redis·Python 서비스는 추가하거나 설치하지 않았다. 승인 폰트의 로컬 검증에는 현재 설치된 `pango-view`와 `fc-match`를 활용한다. 이 추가 런타임 요건은 운영 활성화 전에 별도 확인해야 하며 자동 설치·시스템 폰트 대체는 하지 않는다. 현재 dirty worktree 및 기존 운영 배포는 보존한다.

## 구성

1. `video_productions`: 밈·버전·검수된 사실 스냅샷·대본·장면·자산 권리·산출물·해시·승인 원장.
2. `youtube_publications`: 제작물·채널·해시별 중복 제한, 이어 올리기 세션·영상 ID·처리·공개·사이트 연결 원장.
3. 별도 제작 작업 큐: 점유·임대 갱신·재시도. 기존 ingestion 종속 `processing_jobs`에 업로드 타입을 억지로 추가하지 않는다.
4. 서버 전용 YouTube OAuth: state/PKCE·운영자 재확인·고정 채널·암호화 refresh token. 채널 비밀 및 업로드 세션 URL은 클라이언트 DTO에서 제외.
5. 기존 Node/FFmpeg 렌더러 재사용: 자체 그래픽 베이스·내레이션·자막·출처·워터마크·기술 검사. 동시 렌더 1개, 완성본 전용 비공개 보관.
6. `/admin/video-productions`: 후보·대본 수정·권리 확인·미리보기·비공개 업로드·Studio 제한 확인·공개 승인·오류/복구·삭제 요청.
7. 공개 상세: ‘밈캐치가 설명하는 영상’과 ‘원본 및 관련 출처’를 분리. 공개 상태·처리 성공·임베드 허용 확인 후에만 투영하고 캐시 갱신.

## 필수 불변식

- 임베드 허용은 제작·재게시·상업 이용 권한이 아니다. 이미지/영상/음원/폰트/음성의 제공자, 취득 방법, 편집/YouTube/상업 이용, 표기, 기간·지역, 증빙, 검수자를 기록한다.
- 근거 없는 주장·미검수 사실·막힌/삭제 요청 항목·제작 중 중복 후보는 공개 불가. 자체 영상은 `secondary_reference` 역할이며 유래 증거로 사용 불가.
- 제작물 수정은 렌더·승인을 무효화한다. 승인한 해시와 업로드·사이트 연결 해시가 같아야 한다.
- 외부 업로드 전 원장 생성. 재시도는 기존 세션 조회부터 시작. 결과 불명은 `reconcile_required`로 멈추며 새 업로드를 생성하지 않는다.
- 채널 바꾸기·비공개에서 공개 전환·삭제 조치는 각각 별도 명시적 승인. 공개 제한을 성공으로 표시하지 않는다.
- 삭제 요청은 사이트 비노출을 먼저 적용하고 원격 비공개 작업을 추적한다. 차단 기록 때문에 같은 밈/자산이 재선정되지 않는다.
- 하루 후보 5개·초안 3개·최종 발행 1개는 조정 가능한 시작 설정이며 API 할당량은 별도 설정이다.
- 처리 확인은 전체 관찰 횟수·기한으로 제한하고 실패·종료·거절 상태는 재시도를 종료한다. 실제 사이트 연결 뒤에는 지연 monitor를 한 개씩 이어 등록한다. 큐 실행에는 지속 실행 워커가 필요하다.
- 비공개 선행 업로드는 밈캐치의 안전 정책이다. 미검증 Google API 프로젝트라는 이유만으로 공개 가능/불가능을 추측하지 않고 실제 승인·API 응답·재생을 확인한다.

## 구현 및 검증 순서

| 단계 | 구현 | 완료를 증명할 근거 |
| --- | --- | --- |
| 1 | 계약·DB/RLS·권리·상태 전이 | 회귀 테스트와 실제 격리 PostgreSQL에서 제약·RPC·경합 검증 |
| 2 | 대본·음성·자체 그래픽·렌더·보관 | 실제 FFmpeg MP4와 해상도/길이/오디오/디코드 검사·관리자 미리보기 |
| 3 | OAuth·이어 올리기·검수 발행 | HTTP 프로토콜 테스트와 실제 채널 private 업로드·처리·공개 제한 확인 |
| 4 | 관리자·공개 상세 연결·삭제 처리 | 모바일/모션 감소/콘솔·권한·비공개 비노출·중복/실패 복구 검증 |
| 5 | 운영 활성화 | 승인된 테스트 영상 일반 방문자 재생·임베드·밈 연결, 실제 실행 환경/설정 확인 |

자동 테스트나 테스트 더블만으로 실제 채널 업로드/심사/일반 방문자 재생을 완료로 판단하지 않는다. 외부 인증이 없더라도 위 코드·로컬 실제 렌더·격리 DB·브라우저 검증을 계속 진행하고 남은 운영 활성화 항목을 별도 기록한다.
