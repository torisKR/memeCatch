# 밈카드 구현·운영 기록

2026-10-07 코드 커밋 전의 구현·검증 기록이다. 1,000종 카탈로그와 구현을 준비했고 운영 DB의 추가 마이그레이션 두 개를 적용했다. 웹 배포의 최종 결과와 운영 브라우저 증거는 프로젝트 루트 `.local/meme-cards-20261007/release.html`에 기록한다. 실제 로그인 사용자의 SSR·수령은 운영 계정을 사용하지 않아 별도 검증 범위로 남는다. ChatGPT 앱의 SIWC는 파트너 승인 대기로 별도 보류 중이다.

## 제품 동작과 주요 파일

무료·무제한 수집이며 가격·거래·NFT·희소성·당첨 확률이 없다. 게스트는 `/meme-cards`에서 원하는 카드를 긁어 공개한다. 긁기 기준은 35%이고 키보드용 ‘바로 공개’, 움직임 줄이기, 모바일 조작을 제공한다. 공개한 카드와 복귀 경로를 보존해 기존 Supabase 로그인으로 연결한다. 로그인 후 같은 카드에서 명시적으로 수령해야 하며 자동 수령하지 않는다.

`/my`의 비공개 밈카드 컬렉션은 최근 수령 순 목록·필터·보유 수·소장 배지를 제공한다. 기존 저장 밈과 Plus 폴더·메모는 별개다. 비공개·삭제 카드의 소장 기록과 전체 보유 수는 유지하고 제목·본문은 자리표시자로 가린다. 로그아웃, 다른 탭의 로그인 변화, 포커스 복귀, 계정 변경에는 인증을 재확인하고 이전 사용자의 소장 화면·늦은 응답을 제거한다.

## API와 데이터 경계

| 요청 | 계약 |
| --- | --- |
| `GET /api/meme-cards` | 페이지당 최대 24종. 전체가 공개 가능한 시점에는 42페이지이며 마지막은 16종. 이름·카테고리 검색 지원. |
| `GET /api/meme-cards/collection` | `getUser()`로 실제 로그인 확인. 익명 인증 계정 거절. 본인 소장 페이지 또는 최대 24개 ID의 소장 여부. `private, no-store`. |
| `POST /api/meme-cards/claim` | 같은 출처의 요청만 허용. 최대 1KiB JSON에 `cardId` 하나만 수용. 인증·현재 공개 조건·RLS를 재확인하고 중복 안전하게 수령. |

`meme_collectible_cards`는 카드 배정이며 `user_meme_cards`는 `(user_id, card_id)` 기본 키의 소장 관계다. 넓게 상속된 권한을 회수한 뒤 공개 카탈로그 읽기와 인증된 본인 읽기·삽입만 허용한다. 삽입 권한은 `user_id, card_id` 열로 제한하고 수령 시각은 DB 기본값으로 고정한다. 중복은 `ON CONFLICT DO NOTHING`으로 처리하며 기존 수령 시각을 바꾸지 않는다. 익명 인증 계정은 서버와 RLS 모두에서 거절한다.

공개 조건은 `active`, 부모 밈의 `approved`, `green`, 게시일 존재다. 캐시와 운영자 권한으로 비공개 내용을 우회하지 않는다. 고정 42페이지 데이터만 60초 캐시하고 검색은 그 캐시에 넣지 않는다. 응답 전에 최신 공개 가능 ID를 읽어 숨김·페이지 이동을 반영한다. 기존 관리자 공개 카탈로그 태그도 공유한다. 개인 응답은 공개 캐시에 넣지 않는다.

인증 만료는 401로 로그인 복귀를 안내하고, 일시 장애는 503으로 공개 상태를 유지하며 재시도를 제공한다. 수령 불가 카드는 404/409로 구분한다. 긁기·공개마다 DB 추첨 행을 만들지 않는다. 새 키·유료 의존성·벡터 검색·모델 호출이 밈카드 기능에 필요하지 않다.

## 카탈로그와 아트 근거

현재 공개 조건을 충족한 기존 밈 3,423건을 조사했다. 역사 자료의 초기 적격 후보 821개·정규화 제목 818개는 중간 단계였으며, 최종 참조 연결 후보 묶음 1,305개에서 1,000종을 선정했다. 독립 큐레이션 검토가 제목·설명·별칭 기준과 수정분을 확인했다. 기존 밈·검수·권리·출처 행을 변경하거나 외부 밈을 자체 제작으로 바꾸지 않았다. 자세한 선정 기준은 [카탈로그 문서](meme-card-catalog.md)에 있다.

아트는 74개 공통 기호, 16개 모티프, 8개 구도에 고유 시드 1,000개를 적용한다. 실제 의미 기호 묶음은 66개, 모티프·기호·구도 조합은 153개다. 이는 자체 절차적 SVG이며 개별 수작업 일러스트 1,000개, 세계적 유명도 측정, 모든 URL 재방문, 원본 이미지 이용 허가를 뜻하지 않는다.

검토된 manifest 파일 SHA-256은 `4fd16c2718c11220d45a9c9dbd4b982a26f3a637f6706b279806fa21fbba955b`, 정규화 데이터 SHA-256은 `24f6374ce3858829785c3031c65e5d22fe15fd6bed08b1468042d9bbe132d341`이다. 생성 seed의 SHA-256은 `33cd4c0be13384c19dcbeeaf7ecaac59e3028dfcf88c7544a5bfcb16dcfd551c`이며 `curation-qa.json`에 기록되어 있다.

## 적용 및 검증 기록

운영 migration ledger에 맞춘 적용 파일은 다음 두 개다. 검증된 내용을 유지하며 이름만 실제 적용 시각과 맞췄다.

- `supabase/migrations/20261007083631_meme_collectible_cards.sql`
- `supabase/migrations/20261007083649_meme_collectible_catalog_seed.sql`

담당자가 MCP로 추가 적용한 뒤 정확히 1,000개 배정 일치, 소장 행 0개, RLS·열 권한을 확인했다. 소장 0개는 해당 검증 시점의 값이다. 운영 사용자에게 수령 요청을 보내 QA용 소장 데이터를 만들지 않았다.

| 검증 경로 | 담당자 확인 결과와 한계 |
| --- | --- |
| 자동 검사 | 전체 3,340개 테스트 통과, 타입 검사 통과, lint 오류 0·기존 경고 6개. 이후 아트·서버 변경 대상 23개와 Node 카탈로그 5개 통과. |
| 빌드 | 작업자 1개로 110페이지 빌드 통과. Supabase DNS 접근을 허용한 뒤 성공했으며 앞선 네트워크 실패 기록도 보존했다. |
| SQL | 실제 저장소 스키마의 PostgreSQL mirror에서 RLS·반복 seed·충돌 및 적격 조건 검증 통과. JWT 대체 함수 사용으로 실제 Supabase Auth 검증과 구분한다. |
| 브라우저 | 실제 게스트 291개 검사와 소장 갤러리의 모의 응답 35개 검사 통과. 마우스·터치 34%→35% 공개, 동일 카드 로그인 복귀, 1440·390·320px 및 움직임 줄이기 확인. 실제 인증 SSR·운영 수령과 구분한다. |
| 실제 HTTP | 공개 24·16종 페이지, TMI 검색, 개인 조회·수령의 비로그인 401, 출처 403·입력 400·크기 413 및 개인 no-store 확인. |
| 운영 | DB 적용·읽기 검증 완료. 웹 배포·최종 운영 화면 증거는 별도 릴리즈 기록에 보관한다. |

재검증 명령은 프로젝트 루트에서 설치된 실행 파일을 직접 사용한다. 아래는 재현용이며 이번 문서 작업에서 실행하지 않았다.

```sh
./node_modules/.bin/vitest run --maxWorkers=1 --no-file-parallelism
./node_modules/.bin/tsc --noEmit
./node_modules/.bin/eslint .
node --test scripts/build-meme-card-catalog.test.mjs
node scripts/build-meme-card-catalog.mjs --check
CIRCLE_NODE_TOTAL=1 npm run build
```

SQL 검증 파일은 `supabase/tests/meme_collectible_cards.sql`이다. 실제 적용 이력이 있는 DB에 생성 migration을 다시 실행하지 않고 분리된 검증 환경을 사용한다.

브라우저 검사 도구의 라벨 선택자와 Next 안내용 `role=alert`를 오류로 센 실패 기록은 보존했다. 선택자를 실제 combobox로 지정하고 카드 영역의 오류만 검사한 후 남은 모의 수령 검사를 통과했다. 제품 코드 변경은 필요하지 않았다. 브라우저 실행 중 실제 수령·모델 요청은 0건이다.

## 유지보수와 복구

`mc-0001`부터 `mc-1000`까지 ID·번호·부모 밈·edition·시드 배정을 재정렬하거나 다른 밈으로 재사용하지 않는다. 배포 후 카드 행을 삭제하지 않는다. 공개 불가 콘텐츠는 부모 공개 상태나 `active`로 가리고 소장 관계는 보존한다. 명시적 검토가 필요한 배정 변경은 기존 사용자 소장에 미치는 영향을 포함해 별도 migration으로 다룬다.

카탈로그 수정은 manifest·QA·서버 아트·표시 기호 지원과 생성 seed의 일치를 확인한다. 수량·정규화 제목·계보·별칭·아트 시드·HTTPS 참조의 구조 검사에 더해 사람의 중복·설명 검토를 유지한다. 데이터 공개 조건이 바뀌었다고 기존 밈의 검수·안전도를 수집 기능에 맞춰 변경하지 않는다.

웹 회귀가 발생하면 이전 웹 버전으로 복구하고 추가한 카탈로그·소장 테이블과 소장 데이터를 유지한다. 테이블 삭제나 사용자 수령 기록 삭제로 되돌리지 않는다. 복구 후 공개 가능 여부, 로그인 복귀, 본인 읽기, 숨김 카드 표시와 오류 복구를 확인한다.

새 테이블의 Supabase 보안 검사 지적은 없었다. 성능 검사에는 아직 데이터가 없어 사용되지 않은 최근순 색인과 `card_id` 역색인 미설치가 INFO로 표시됐다. 소장 조회는 사용자별 기본 키·최근순 색인을 사용하고 카드 배정은 삭제·재사용하지 않으므로, 현재 역색인은 추가하지 않았다. 카드 ID를 변경·삭제하는 운영을 도입한다면 [외래 키 색인 점검](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys)을 포함한다.
