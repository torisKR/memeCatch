# HG-004 (c) 태그 backfill — C안 구현안 및 영향 분석

> 대상: `DECISIONS.md` HG-004 추천안 **C**(태그만 자동 backfill, 중복 병합·alias 정리는 수동).
> 이 문서는 **제안서**다. 소스 코드·DB를 변경하지 않았다. 모든 수치는 2026-08-04
> 프로덕션 PostgREST **GET 전용** 조회(anon key)로 실측했다.

---

## 0. 요약 (결론 먼저)

1. **`tags` 테이블과 `meme_tags_map` 둘 다 물리적으로 0행이다.** 태그 backfill은
   "비어 있는 매핑 채우기"가 아니라 **어휘 자체를 새로 만드는 일**이다.
2. category 기반 규칙(R1)만 돌리면 DQ-M2(태그 0건 3,904건)는 **즉시 0이 되지만
   추천 품질은 1도 나아지지 않는다.** `getRelatedMemes`가 이미 category로 폴백하기
   때문이다. **검사 통과를 목적으로 R1을 넣는 것은 지표 조작이다.**
3. **실질 효과는 제목·alias 키워드 규칙(R2)에서만 나온다** — 1,018건(26.1%)에
   1,142개 매핑.
4. **대형 태그를 넣으면 추천이 오히려 나빠진다.** `lib/queries.ts:229-234`의 태그
   조회가 `.limit(30)`을 **정렬 없이** 걸고, 태그 일치 문서에 가중치 **3점**(동일
   카테고리 2점보다 높음)을 준다. 1,885건짜리 「유행어」 태그를 붙이면 임의의 30건이
   동일 카테고리 상위 문서를 밀어내고 첫 화면에 올라온다.
5. **따라서 권고안은 R2만 적용(1,142행)** 이다. R1·R3(연도대)는 코드 수정 전까지 보류.
6. R2만 적용하면 **색인 문서 수는 145에서 그대로다(+0).** 이 작업은 색인이 아니라
   추천을 위한 것이다 — 색인 효과로 정당화하면 안 된다.

## 2. 태그 후보 생성 규칙

### 2.0 문자열 정규화

```
norm(s) = NFC(s) 에서 [공백 · , - – — / ( ) [ ] " ' ’ “ ” ! ? ~ : ; .] 전부 제거
```

- **한글 패턴**: `norm(패턴) ⊂ norm(제목 + aliases)` 부분일치.
  「나는솔로」가 「나는 솔로」·「나는, 솔로」를 모두 잡는다.
- **ASCII 패턴**(`AI`, `BTS`, `CM송`의 CM 부분 등): 원문에 **단어 경계** 정규식
  `(?<![A-Za-z0-9])PAT(?![A-Za-z0-9])`, 대소문자 무시.
  이 규칙이 없으면 「**AGAIN** 2002」가 `AI` 태그를 받는다 (실제로 v1에서 발생 —
  §4 참조).
- 매칭 대상은 `title` + `aliases[]`. **alias에서만 태그를 얻는 문서가 224건**이라
  빼면 손실이 크다. 예: `27zs8e4n` 「GPT체」 aliases `["AI 문체","GPT말투"]` → `AI`.

## 5. 영향 분석

### 5.1 관련 밈 추천 — ★ 가장 큰 영향, 대형 태그 금지 근거

`lib/queries.ts:216-297` `getRelatedMemes`:

```ts
const { data: mapRows } = await supabase
  .from("meme_tags_map")
  .select("meme_id")
  .in("tag_id", tagIds)
  .neq("meme_id", meme.id)
  .limit(30);          // ← 정렬 없음
...
const score = (m) =>
  (taggedIds.has(m.id) ? 3 : 0) +      // 태그 일치 = 최고 가중치
  (m.category === meme.category ? 2 : 0) +
  (Math.abs(m.origin_year - meme.origin_year) <= 2 ? 1 : 0);
```

- `.limit(30)`에 `order`가 없다 → PostgREST가 돌려주는 30건은 **사실상 임의**다.
- 그 임의의 30건이 **3점**을 받아 `trend_score` 내림차순으로 정제된 동일 카테고리
  후보(2점)를 **전부 밀어낸다**.
- 「유행어」(1,885건 예상) 같은 태그를 붙이면 상세 첫 화면의 관련 밈 6칸이
  **무작위 유행어 문서로 채워진다.** 지금(태그 0건)보다 **나빠진다.**
- R2 태그 중 30건을 넘는 것도 11종 있다(챌린지 361 … 스포츠 36). 다만 이들은
  최소한 **같은 주제**를 공유하므로 임의 30건이어도 의미가 있다. R1(263~1,883건)·
  R3(19~1,494건)은 그 조건을 만족하지 않는다.

→ **Phase 1은 R2만.** R1·R3는 `getRelatedMemes`에 `order("trend_score", desc)`가
들어간 뒤에 재검토한다(후속 backlog, §10).

### 5.2 충실도(`lib/content-depth.ts`) → 사이트맵·robots

`isIndexableMeme`은 `proseChars ≥ 250` **AND** `score ≥ 5`를 모두 요구하고, 태그는
`tagCount ≥ 3`일 때 **1점**만 준다.

전수 재계산(현재 판정 145건을 그대로 재현하는 모델로 검증):

| 조합 | 색인 문서 | 신규 진입 |
| --- | ---: | ---: |
| 현재 | 145 | — |
| **R2만 (권고)** | **145** | **+0** |
| R1+R2 | 148 | +3 |
| R1+R2+R3 | 165 | +20 |

R2만으로는 태그 3개에 도달하는 문서가 3건뿐이고, 그 3건은 이미 5점 미만이 아니라
**색인 문서가 한 건도 늘지 않는다.** R1을 얹어야 겨우 3건 늘어난다(전부 4점→5점,
산문 250자는 이미 통과): `nzn44kxr` 안우진 학폭 논란 WBC 제외(278자) ·
`p8z37ks6` 타진요 사건(328자) · `zhhzds88` 하니 국감 SNL 패러디 논란(302자).

**색인 효과는 3,904건 중 0~3건이다.** 태그 backfill의 명분은 색인이 아니라 추천이다.

> 검증: 위 계산식을 그대로 재현한 모델이 현재 판정 **145건을 정확히 재현**한다
> (`DATA_QUALITY_REPORT.json`의 `depth.substantial = 145`와 일치).

### 5.3 랭킹 `trend_score` — 순서 불변 확인

`meme_ranking_completeness()`는 태그가 1개라도 있으면 **+5점**을 준다
(`20260715003000_content_quality_ranking.sql:44-46`). `compute_trend_scores()`는:

```sql
trend_score = case
  when eligible and safety_level='green'  then 300 + signal + completeness/10.0
  when eligible and safety_level='yellow' then 200 + signal + completeness/10.0
  when eligible                            then 100 + signal + completeness/10.0
  else least(99, completeness/2.0 + signal)     -- ← 99 클램프
end
```

- 자격 문서: +0.5, 비자격 문서: +2.5. 티어 베이스(100/200/300 vs ≤99)가 달라
  **티어 역전은 구조적으로 불가능**하다.
- 유일한 위험은 비자격 티어의 **99 클램프**로 순서가 뭉개지는 것. 실측:

| 구간 | 문서 |
| --- | ---: |
| `trend_score ≥ 100` (자격) | 1,683 |
| `96.5 ≤ trend_score < 100` (클램프 위험대) | **0** |
| `trend_score < 96.5` | 2,221 |

**위험대가 0건**이므로 +2.5를 더해도 99에 닿는 문서가 없다. **티어·순위 역전 없음.**
단 R2만 적용하면 1,018건만 +5를 받으므로 비자격 티어 내부에서 미세한 재정렬은 생긴다

받아 이 재정렬조차 사라진다.

### 5.4 검사 지표

| 검사 | 현재 | R2만 (권고) | R1 포함 |
| --- | ---: | ---: | ---: |
| DQ-M2 태그 없음 | 3,904 (100%) | 2,886 (73.9%) | **0** |

**R1로 DQ-M2를 0으로 만드는 것을 권하지 않는다.** category 컬럼을 태그로 복사한 것에
불과해 `getRelatedMemes`의 category 폴백과 정보량이 같다. 검사기는 통과하고 사용자
경험은 그대로인 전형적 지표 조작이다. 루프 003·007이 지켜 온 "근거보다 세게 말하지
않는다" 원칙과 충돌한다.

### 5.5 권한·RLS

```sql
create policy tags_public_read     on tags          for select using (true);
create policy tags_map_public_read on meme_tags_map for select using (true);
create policy tags_operator_write     on tags          for all using (is_operator()) ...;
create policy tags_map_operator_write on meme_tags_map for all using (is_operator()) ...;
```

- **프리뷰 스크립트는 anon 키만 쓴다 → RLS가 쓰기를 물리적으로 거부한다.**
  코드 실수로 POST를 보내도 데이터가 바뀌지 않는다.
- 적용은 operator 세션 또는 service_role이 필요하다. `LOOP_STATE.md` 위험 6번:

  → **적용 경로는 Supabase SQL Editor(operator)** 를 기본으로 한다. §7의 SQL은 그 전제다.
