기존 데이터와 검색 재사용

기존 PostgreSQL·pgvector·384차원 E5 검색을 재사용한다. 질의 임베딩이 설정된 경우 하이브리드 검색을 사용하고, 사용 불가하면 키워드 검색으로 전환한다. 공개 익명 클라이언트와 RLS로 approved·limited 자료만 읽는다.

답변과 근거의 경계

검색 자료와 질문을 명령으로 실행하지 않는다. 조회한 문서 안의 인용 ID만 허용하고, 모델이 만든 URL·HTML·Markdown 링크는 채택하지 않는다. 링크는 서버가 조립한다. 실제 인용 문서의 날짜 정확도가 exact가 아니고 기원·연도 정보가 있으면 고정 불확실성 안내를 붙인다. 생성문의 모든 사실을 자동 인증하지 않는다.

자료 없음은 empty, 생성 설정이나 무료 모델 장애는 검색 자료 retrieved로 표시한다. 생성 성공만 generated로 구분한다. 출처 URL의 존재가 사실·권리 검증을 뜻하지 않는다.

열기만으로 요청하지 않으며 관리자·인증 화면에서는 숨긴다. 답변은 일반 텍스트다. 제출 전에 질문과 공개 자료의 AI 서비스 전달을 안내하고, 화면 대화는 최대 6개만 메모리에 보관한다. 별도 영구 대화 테이블은 만들지 않는다. 제공자 자체 로그는 별도다.

로컬 opencodex 주소를 운영 환경에 복사하면 연결할 수 없다. 구현은 Vercel에서 이 경로를 사용하지 않는다. 외부 HTTPS 서비스·인증·운영 검토 없이 터널이나 공개 노출을 만들지 않았다.

캐시가 적중해도 검색과 현재 공개 자료 조회가 먼저 필요하다. 새 생성·공유 작업 뒤에는 공개 상태와 내용을 다시 확인한다. 따라서 캐시는 생성 호출을 줄이지만 Supabase 조회나 Vercel 함수 실행을 없애지 않는다. 프로세스 재시작·인스턴스 분리에 따라 캐시도 분리된다.

벡터 검색은 관련 자료를 찾는 기능이다. DB 읽기·임베딩·생성 비용이 추가될 수 있어 PostgreSQL 성능 향상이나 사용료 감소를 자동 보장하지 않는다. 실제 호출량·응답 시간·전송량의 전후 측정이 필요하다. 새 Redis나 과금 계정을 추가하지 않았다.

무료 라우터의 가격 제한은 무료 호출 한도·가용성·Supabase·Vercel 리소스 한도를 없애지 않는다. 이번 보고에서 월별 Usage를 확인하지 않아 무료로 버틸 방문자 수나 비용 절감률을 산정하지 않는다. 기존 분석은 2026-10-02 무료 플랜·비용 보고서를 참고하되 당시 관측과 한도로 읽어야 한다.

3. 탐색·콘텐츠와 검수·재등록

  • 홈 최근 6개 필터와 전체 검색 GET 폼·CTA를 구분하고 기존 5개 locale에 반영했다. 대표 썸네일을 지원하며 없으면 추상 fallback을 유지한다. 관찰한 최신 6개에는 썸네일 메타데이터가 없었다.
  • SearchInput의 서버 응답·뒤로가기 동기화와 늦은 응답 처리를 보완했다. 빈 탐색 결과의 제보 이름은 로그인 이동에서도 allowlist와 100자 범위 안에서 보존한다.
  • 제목과 같은 요약은 등록 전에 차단한다. NFKC 제목·별칭 중복 검사를 통일하고, 빈 정규화 키의 기호 제목을 오탐하지 않는다. 무효 공개 URL을 근거 수에 포함하지 않는다.
  • 대기 문서 생성 → 출처 저장 성공 → 기존 검수 상태 전이로 승인 순서를 바꿨다. 부분 저장 ID를 유지해 실패 뒤 재시도에서 새 문서가 다시 생기는 일을 줄였다.
  • 게시 뒤 상태 확인·감사·캐시 처리 실패는 게시 결과와 구분해 경고한다. 여러 운영자의 동시 승인 전체 원자성은 아직 보장하지 않는다.
