## 1. 근거 — 실측값

### 1-1. 도크 실제 높이 vs 예약된 높이

`document.querySelector('aside[aria-label="쿠팡 파트너스 광고"]')` 및 그 직전 형제(스페이서)의
`getBoundingClientRect()`:

| 뷰포트 | iframe h | 도크 실측 높이 | 스페이서 예약 | 차이 |
| --- | ---: | ---: | ---: | ---: |
| 1280×800 (데스크톱) | 120px | **151px** | 140px | **−11px** |
| 500×806 (모바일) | 100px | **131px** | 120px | **−11px** |

원인은 산술이다. `coupang-dock.tsx:53`은 `const dockH = h + 20;`으로 고지줄을 약 18~20px로
잡았지만, 실제 고지행 높이를 결정하는 것은 **닫기 버튼 `h-6`(24px)** 이다
(`className="... h-6 w-6 ..."`, 부모가 `items-center`). 실제 크롬 높이:

```
border-t          1px   (className="... border-t border-border ...")
pt-0.5            2px   (고지행 wrapper)
고지행            24px   (닫기 버튼 h-6가 지배 — <p>의 leading-4는 16px이라 밀린다)
pb-1              4px   (iframe wrapper)
────────────────────
합계             31px   → dockH = h + 31
```

검산: `120 + 31 = 151` ✅ / `100 + 31 = 131` ✅ — 실측과 정확히 일치.

### 1-2. 11px가 실제로 가리는 것

문서 최하단까지 스크롤한 상태(`scrollHeight` − 뷰포트):

| route / 뷰포트 | footer bottom (문서 좌표) | `scrollHeight` | 문서 끝 여유 | 도크 높이 | 가려지는 footer |
| --- | ---: | ---: | ---: | ---: | ---: |
| `/rankings` 1280×800 | 1746 | 1886 | 140 | 151 | **11px** |
| `/rankings` 500×806 | 3113 | 3296 | 183 (=120 + body `pb-16` 64) | 131 (도크는 `bottom-16`) | **12px** |

푸터 마지막 11~12px(하단 보더·여백 영역)가 항상 도크 밑에 깔린다. 작지만 이것이
LOOP.md 「하단 고정 내비게이션과 콘텐츠가 겹치지 않는가」가 문자 그대로 걸리는 지점이고,
C안이 고칠 수 있는 **유일한** 겹침이다.

### 1-3. C안이 고칠 수 없는 겹침 (정직하게 기록)

초기 스크롤 위치(`scrollY=0`)에서 도크가 덮는 콘텐츠:

| route / 뷰포트 | 덮인 요소 | 가려진 양 |
| --- | --- | ---: |
| `/rankings` 500×806 | **4위 카드** (top 591, h 114) | **94px (82%)** |
| `/rankings` 500×806 | 5위 카드 (top 713) | 29px (25%) |
| `/rankings` 1280×800 (2단) | 7·8위 카드 (top 591, h 114) | 각 56px (49%) |
| `/memes/[key]` 500×806 | Instagram reel iframe (top 331, h 580) | 131px (도크 전체) |
| `/memes/[key]` 1280×800 | TikTok player iframe (top 248, h 576) | 151px (도크 전체) |

`BACKLOG.md` DES-004의 「랭킹 4위 카드가 도크에 가려진다」는 **재현됐다**(82%).
다만 이것은 **화면 중간을 덮는 겹침**이라 문서 하단 패딩으로는 원리적으로 해결되지
않는다. 스크롤하면 도달할 수 있으므로 "영구 차단"은 아니다.
**이 항목이 사라지려면 B안(고정 해제)이어야 한다** — C안을 택하는 이상 남는 비용으로
기록하고, DES-004 완료 조건을 「문서 끝 콘텐츠가 가려지지 않는다」로 좁혀야 한다.

### 1-4. 광고 컨테이너 크기 예약 — 이미 되어 있다

메인 프레임에서 관측한 도크 iframe:

```json
{"src":"https://ads-partners.coupang.com/widgets.html?id=1006385&template=caro",
 "w":"360","h":"100","styleH":"100px","rectH":100}
```

`width`/`height` 속성 + 인라인 `style.height`가 모두 있고 실측 rect가 정확히 100px다.
**추가로 예약할 것이 없다.**

메인 프레임의 쿠팡 리소스 목록(`performance.getEntriesByType('resource')`)에는
`widgets.html` iframe 문서 **1건뿐**이다. 루프 012가 범인으로 지목한
`img1a.coupangcdn.com/image/mobile/ajax-loader.gif`는 **목록에 없다** — 교차 출처
iframe 내부 리소스다. 따라서 그 이미지의 시프트는 iframe 자신의 문서에 귀속되며,
부모 컨테이너에 `min-height`를 주는 것으로 손댈 수 없고 **사이트의 필드 CLS에도
집계되지 않는다**.

### 1-5. 상세 CLS의 진짜 원인 — `AuthInvite`

메인 프레임에 `PerformanceObserver({type:'layout-shift', buffered:true})`를
`initScript`로 주입해 관측했다(DevTools의 "potential root cause" 휴리스틱이 아니라
브라우저가 보고하는 `sources[].node`를 직접 읽었다).

| 실행 | 뷰포트 | 캐시 | 메인프레임 CLS | 시프트 수 |
| --- | --- | --- | ---: | ---: |
| 상세 `nrk9ryzn` | 500×806 | 콜드(isolatedContext) | **0.2109** | 1 |
| 상세 `nrk9ryzn` | 500×806 | **웜**(쿠팡 transferSize=0) | **0.2095** | 1 |
| 상세 `nrk9ryzn` | 1280×800 | 웜 | **0.0721** | 1 |
| `/rankings` | 500×806 | 콜드 | **0.0000** | 0 |

세 번 다 **단일 시프트**이고 `sources[0].node`가 같다:

```
DIV.lg:grid.lg:grid-cols-[minmax(0,5fr)_minmax(0,6fr)].lg:items-start.lg:gap-8
  모바일:   y 77 → 276.5   (+199.5px)
  데스크톱: y 77 → 193.75  (+116.75px)
```

= `app/(default)/memes/[key]/page.tsx:246`의 2단 그리드다.
그 바로 위에 있는 것이 `<AuthInvite />`(`page.tsx:242`)이고, 마운트 후 실측 높이는
**모바일 176px / 데스크톱 93px**. `main`의 `space-y-6`(24px 간격)을 더하면
`176+24 = 200 ≈ 199.5`, `93+24 = 117 ≈ 116.75` — **밀린 거리와 정확히 일치한다.**

`components/auth-invite.tsx:46`은 `if (status !== "guest") return null;`로 세션 판정
전에는 아무것도 렌더하지 않는다. 판정이 끝나는 순간(콜드 772ms / 웜 665ms / 데스크톱
270ms) 카드가 통째로 삽입되며 아래 본문 전체를 밀어낸다.

**웜 캐시에서도 0.2095가 나온 것이 결정적이다.** 루프 012는 「광고 이미지가 캐시돼
있으면 이동이 없다 → 웜 CLS 0.00」으로 원인을 광고에 귀속했다. 쿠팡 리소스가
`transferSize: 0`(캐시 적중)인 실행에서 CLS가 그대로 0.21이면, 광고 이미지는 원인이
아니다.

참고: 같은 트레이스에서 DevTools `CLSCulprits`는 **여전히** `ajax-loader.gif`를
「Potential root causes」로 내놓는다(루프 012와 동일). 이 인사이트는 시프트 시각
근처의 크기 미지정 이미지를 **서브프레임 포함**해서 상관관계로 고르는 휴리스틱이다.
실제 시프트 노드는 `sources[].node`에만 있다. → 재측정 절차(§5)에 관측자 병행을 필수로 넣었다.

`initScript`:

```js
window.__ls = [];
new PerformanceObserver((l) => {
  for (const e of l.getEntries()) {
    if (e.hadRecentInput) continue;
    window.__ls.push({
      t: Math.round(e.startTime),
      value: Number(e.value.toFixed(4)),
      sources: (e.sources || []).map((s) => ({
        node: s.node
          ? s.node.nodeName +
            (typeof s.node.className === "string" && s.node.className
              ? "." + s.node.className.split(" ").slice(0, 3).join(".")
              : "")
          : "none",
        prevY: s.previousRect ? s.previousRect.y : null,
        curY: s.currentRect ? s.currentRect.y : null,
      })),
    });
  }
}).observe({ type: "layout-shift", buffered: true });
```

수집 함수:

```js
async () => {
  await new Promise((r) => setTimeout(r, 4000)); // 세션 판정·lazy iframe 마운트 대기
  const coupangCached = performance
    .getEntriesByType("resource")

  return {
```
